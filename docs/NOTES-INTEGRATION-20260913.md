# EasyRead 2.0.0 — Notes 整合

## 产品与交互

| Before | After | Why |
| --- | --- | --- |
| 重点与批注分开显示、分别存储 | 一个 Notes（笔记）列表、一个活动数据集合 | 沿着阅读过程保存记录，而不是要求用户选择数据系统 |
| 划重点后需要另建批注 | 保留快捷「划重点」；原卡片可「添加我的观点」 | 原地补充内容，保留 ID、引用和位置 |
| 只能针对选中文字写批注 | 列表底部可添加整页笔记 | 容纳对整篇文章的思考 |
| 两类列表各自排序 | 正文笔记按原文位置排序；整页笔记始终最后 | 与阅读顺序一致 |
| 重点设置与批注设置分散 | 设置中的「笔记」管理显示、作者和导出 | 统一产品概念，保留原有设置值 |

主窗口和网页侧栏复用同一套卡片。引用型笔记显示正文对应编号、引用及可选观点；整页笔记不占用正文编号，采用独立卡片。短列表的整页笔记自然位于下方。编辑在原卡片位置进行，Enter 保存、Shift+Enter 换行、Esc 取消。清空引用型笔记的观点不会删除引用；整页笔记不能保存为空。

右键选中文字仍可快速「划重点」。已有笔记可以编辑或移除；不选文字也可写整页笔记。刷新后的正文标记恢复继续使用已有引用匹配能力。正文找不到时保留记录并提示，不凭空高亮其他内容。

## 数据与兼容

活动数据统一存入 `chrome.storage.local.notes`，沿用既有页面 URL 归一化规则。每页仍是包含 `notes` 数组的对象，保留旧字段；条目包含 ID、编码后的 `selectionText`、可选 `prefix` / `suffix` / `textPosition`，以及 `scope`（text/page）、`comment`、`author`、创建与更新时间。作者偏好继续使用 `annotationAuthor`。

首次发现旧 `annotations` 时，将其转换为同一集合内的笔记；旧批注 ID 增加 `annotation:` 命名空间并保留 `legacyAnnotationId`，避免与旧重点冲突。相同 ID 的不同记录不会被静默覆盖。迁移在一次 storage 写入中保存统一结果、清空活动 `annotations`，并首次建立 `notesMigrationBackupV1` 原始快照。写入失败时不会先清空旧数据。

快照仅用于维护恢复，不参与展示，也不会在用户删除后自动恢复记录。普通删除笔记不会删除该迁移快照；清空全部本地数据才会一起删除。需要回退代码时，应先导出当前完整备份；旧版本无法完整理解新笔记，不能仅靠切换代码回退数据。迁移快照可用于人工恢复升级前状态，但不含升级后新增记录。

旧备份导入同样执行归一化；重复导入保持幂等，较旧内容不会覆盖较新的编辑。新增、编辑、删除、迁移和导入通过后台队列串行处理，避免多个界面同时写入造成丢失。Markdown 导出包含引用和观点；旧自定义模板未包含观点占位符时仍会补充观点，避免导出遗漏。

## 排序与界面稳定性

优先使用当前正文文本索引定位，结合引用前后文和已保存位置识别重复文本。无法定位的引用型笔记使用已有位置或稳定的时间顺序，仍在整页笔记之前。整页笔记单独按创建顺序排列。编辑器不因普通存储刷新被重建，新引用笔记的草稿也插入对应正文位置。

主窗口入场动画改为一次性动画，避免键盘输入后切回鼠标重新播放缩放，导致第一次按钮点击偏移。共享卡片的渲染缓存包含语言，切换语言时重新渲染文案。

## 验证与边界

- 单元测试：迁移快照、写入失败、并发保存、重复导入、ID 冲突、原地补充观点、排序及 Markdown 兼容。
- 隔离的 Edge Manifest V3 场景：旧数据恢复、正文/整页笔记新增编辑删除、草稿位置、显示开关、主窗口/侧栏一致性、备份恢复及中英文界面。
- 原生工具栏弹窗尺寸与交互稳定性检查，覆盖 Tab 切换、滚动和键盘操作。
- 不新增远程传输、权限或统计；没有读取或修改个人浏览器数据。

任意网站的动态 DOM、重复正文和已删除原文无法保证全部准确定位；未匹配的笔记不会被丢弃。安装更新后需重新加载扩展，并刷新已经打开的网页，使页面脚本与新后台版本一致。
